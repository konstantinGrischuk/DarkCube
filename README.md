**DarkCube OS** — минималистичная серверная платформа с нулевыми скрытыми зависимостями. Собственная сборочная цепочка, полная управляемость через веб-панель и безопасность корпоративного уровня.

<hr style="border: 1px solid #8A2BE2; width: 100%;">

**Редакции:**

* **Docker Container** — минимальный образ для развертывания в контейнерах (без ядра и загрузчика).
* **Core** — серверная редакция без графического интерфейса. Идеально подходит для серверов, баз данных и веб-хостинга.
* **Desktop** — полноценная рабочая станция с графическим интерфейсом (GUI) для повседневного использования.

## 🛡️ ГОСТ-криптография «из коробки»

DarkCube OS — это не просто дистрибутив с установленным пакетом `openssl-gost`. Мы обеспечиваем **глубокую интеграцию** алгоритмов ГОСТ 34.12-2015 на уровне ядра и системных утилит.

### Что сделано

| Компонент | Статус | Реализация |
| :--- | :---: | :--- |
| Ядро: Магма (ГОСТ 34.12-2015) | ✅ | Собственный модуль, 379 строк |
| Ядро: Кузнечик (ГОСТ 34.12-2015) | ✅ | Собственный модуль, 695 строк |
| Ядро: Streebog (ГОСТ 34.11-2012) | ✅ | Встроен в upstream, включён нами |
| Режимы ECB / CBC / XTS | ✅ | Реализованы внутри модулей |
| `dm-crypt` + ГОСТ | ✅ | Полный цикл проверен |
| LUKS2 + Кузнечик XTS | ✅ | `luksFormat`, `luksOpen`, I/O |
| LUKS2 + Магма CBC | ✅ | Полный цикл проверен |
| OpenSSL: Streebog256/512 | ✅ | Провайдер `gostprov` собран |

### Поддержка на уровне ядра

В ядро интегрированы модули шифрования **«Кузнечик»** и **«Магма»**. Они регистрируются в Crypto API и доступны всем системным компонентам, использующим шифрование (LUKS, dm-crypt, IPsec).

**Важно:** в upstream-ядре Linux ГОСТ-блокчейзеров **нет** — только Streebog. Магма и Кузнечик отсутствуют в mainline начиная с 4.x и по сей день, включая 7.3. Наши модули — собственная реализация, проверенная по эталонным тест-векторам RFC.

### Имена алгоритмов в Crypto API

Модули регистрируют несколько вариантов имён, потому что разные компоненты ищут их по-разному:

| Имя | Кто использует |
| :--- | :--- |
| `kuznyechik`, `magma` | базовый блок |
| `ecb(kuznyechik)`, `cbc(kuznyechik)`, `xts(kuznyechik)` | `dm-crypt` |
| `kuznyechik-ecb`, `kuznyechik-cbc`, `kuznyechik-xts` | `cryptsetup` (проверка доступности) |
| `magma-ecb`, `magma-cbc` | `cryptsetup` |

## 💾 Шифрование дисков (LUKS2)

По умолчанию `cryptsetup` настроен на использование **Кузнечика (Kuznyechik)** в режиме `XTS`.

### Правильный синтаксис

Критично указывать **три части** в имени шифра:

```bash
# ✅ Правильно
cryptsetup luksFormat --type luks2 \
  --cipher kuznyechik-xts-plain64 \
  --key-size 512 --hash sha256 \
  /dev/sdX
```

```bash
# ❌ Неправильно — cryptsetup примет "xts" за IV-режим
cryptsetup luksFormat --cipher kuznyechik-xts ...
```

**Причина:** в коде `cipher_dm2c()` библиотека `libcryptsetup` разбирает строку через `sscanf("%[^-]-%s")`. Если частей две (`cipher-mode`), вторая считается IV-режимом, а режим шифрования теряется.

### Почему не Магма?

Алгоритм «Магма» имеет размер блока **8 байт**. Режим XTS требует **16 байт** (`XTS_BLOCK_SIZE` в ядре). Поэтому Магма **не может** использоваться в LUKS2 по умолчанию. Она доступна в режимах ECB и CBC:

```bash
cryptsetup luksFormat --cipher magma-cbc-plain64 --key-size 256 ...
```

## 📊 Производительность

### Методика измерений

Замеры проводились двумя способами:

1. **Эмулятор QEMU** (`-accel tcg`, без KVM) — искажает скорость в **6–8 раз** вниз
2. **Реальное железо** — Intel Core i7-7700 @ 3.6 ГГц, нативная компиляция `gcc -O2 -march=native`

> ⚠️ Первые замеры в QEMU дали 5 МБ/с. Это **не** реальная скорость — виноват эмулятор, а не код.

### Почему ГОСТ медленнее AES

| | AES | ГОСТ |
| :--- | :--- | :--- |
| Аппаратное ускорение | **AES-NI** — отдельные инструкции CPU | **отсутствует** |
| Инструкций на блок | 1–2 (`aesenc`) | сотни |
| Доступность | в каждом CPU с 2010 г. | только специализированные чипы |

AES-NI есть в любом современном процессоре. Аппаратных ускорителей ГОСТ в массовых CPU нет — они существуют лишь в сертифицированных СКЗИ (платы, USB-токены).

### Где это работает

* **✅ Шифрование ноутбуков и рабочих станций** — 43 МБ/с с запасом покрывает потребности десктопа
* **✅ Защищённые каналы** — VPN и SSH до 100 Мбит/с
* **⚠️ Серверы баз данных** — приемлемо, но может стать узким местом при высоких нагрузках
* **❌ Файловые серверы 10 Гбит/с** — программный ГОСТ не обеспечит нужную скорость

## 🔧 Сборочный конвейер

### Структура скриптов

Скрипты пронумерованы по порядку запуска. Десятки — этап работы.

```
01-setup-mock-profile.sh     ┐
02-setup-buildroot.sh        ├─ установка окружения (один раз)
03-setup-mock-tune.sh        ┘

10-init-state.sh             ┐
11-inventory.sh              ┴─ инициализация проекта

20-fetch-srpm.sh <пакет>     ── подготовка исходников

30-pipeline.sh run           ┐
31-build-package.sh <пакет>  ┴─ сборка

40-fix-recipes.sh <пакет>    ┐
41-disable-tests.sh <пакет>  ┴─ автоправки

50-sign.sh                   ┐
51-make-repodata.sh          │
52-make-manifest.sh          ├─ публикация
53-publish.sh                ┘

90-report.sh                 ── контроль
```

### Быстрый старт

```bash
# Первичная настройка
tools/01-setup-mock-profile.sh
tools/02-setup-buildroot.sh
tools/10-init-state.sh
tools/11-inventory.sh

# Сборка
tools/30-pipeline.sh run --limit 40
tools/30-pipeline.sh run --retry-failed

# Публикация
tools/53-publish.sh
```

### Порядок публикации (критично)

```
подпись пакетов → генерация repodata → манифест
```

Подпись изменяет байты файла, поэтому repodata **обязательно** генерируется после неё. Иначе `dnf` обнаружит несовпадение контрольных сумм.

### Совместимость

| Версия ядра | Код модулей | Конфиг |
| :--- | :---: | :---: |
| 6.12 (AlmaLinux 10) | ✅ собран и проверен | ✅ |

А вот конфиг переносить нельзя: между версиями добавились и переименовались сотни опций. Правильный путь — `defconfig` новой версии + наш скрипт отключения подсистем + ГОСТ-опции.
