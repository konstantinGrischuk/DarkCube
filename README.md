**DarkCube OS** — минималистичная серверная платформа с нулевыми скрытыми зависимостями. Собственная сборочная цепочка, полная управляемость через веб-панель и безопасность корпоративного уровня.

<hr style="border: 1px solid #8A2BE2; width: 100%;">

**Редакции:**

* **Docker Container** — минимальный образ для развертывания в контейнерах (без ядра и загрузчика).
* **Core** — серверная редакция без графического интерфейса. Идеально подходит для серверов, баз данных и веб-хостинга.
* **Desktop** — полноценная рабочая станция с графическим интерфейсом (GUI) для повседневного использования.

## 🛡️ ГОСТ-криптография «из коробки»

DarkCube OS — это не просто дистрибутив с установленным пакетом `openssl-gost`. Мы обеспечиваем **глубокую интеграцию** алгоритмов ГОСТ 34.12-2015 на уровне ядра и системных утилит. ГОСТ используется по умолчанию везде, где это технически возможно.

### Поддержка на уровне ядра
В ядро Linux 6.12 (Alma) интегрированы модули шифрования **«Кузнечик»** и **«Магма»**. Они регистрируются в Crypto API и доступны всем системным компонентам, использующим шифрование (LUKS, dm-crypt, IPsec).

### Шифрование дисков (LUKS2)
По умолчанию `cryptsetup` настроен на использование **Кузнечика (Kuznyechik)** в режиме `XTS`. Это стандарт для новых систем, обеспечивающий максимальную совместимость и безопасность.

**Почему не Магма?**
Алгоритм «Магма» имеет размер блока 8 байт. Режим XTS (используемый в LUKS2) требует размер блока 16 байт. Поэтому Магма **не может** использоваться в LUKS2 по умолчанию. Она доступна только в режиме CBC для специфических задач.

### Производительность (Честные цифры)
Мы провели реальные замеры на железе (Intel i7-7700) и в эмуляторе QEMU. Программная реализация ГОСТ уступает AES из-за отсутствия аппаратного ускорения (AES-NI), но этого достаточно для большинства задач.

| Алгоритм | Режим | Скорость (реальное железо) | Отн. AES |
| :--- | :--- | :--- | :--- |
| **AES-256** | XTS | 3735 МБ/с | 1.0x |
| **Кузнечик** | XTS (LUKS2) | **43.0 МБ/с** | 0.011x |
| **Магма** | CBC | **39.5 МБ/с** | 0.010x |

> *Подробный отчет о тестировании и причинах различий в скорости доступен в [docs/GOST-PERFORMANCE.md](docs/GOST-PERFORMANCE.md).*

### Где это работает?
*   **✅ Шифрование ноутбуков и рабочих станций**: 43 МБ/с с запасом покрывает потребности десктопа.
*   **✅ Защищённые каналы**: Подходит для VPN и SSH-соединений до 100 Мбит/с.
*   **⚠️ Серверы баз данных**: Приемлемо, но может стать узким местом при высоких нагрузках.
*   **❌ Файловые серверы 10 Гбит/с**: Программный ГОСТ не обеспечит нужную скорость. Требуются аппаратные ускорители.

### Дорожная карта
*   [x] Патч ядра (Crypto API).
*   [x] Настройка `cryptsetup` по умолчанию на Кузнечика.
*   [ ] Интеграция `openssl-gost-engine` (в процессе).
*   [ ] Патч `openssh` для ГОСТ-шифров.
*   [ ] Поддержка ГОСТ в `curl` и `wget`.

## 🏗️ Архитектура конвейера

Проект собирается с помощью полностью автоматизированного и возобновляемого конвейера. Все пакеты получают собственный суффикс версии: `<имя>-<версия>-<release>.p10.darkcube1.<арх>`.

```text
┌─────────────────────────────────────────────────────────────────────┐
│  1. ИНВЕНТАРИЗАЦИЯ                                                  │
│     Список исходных пакетов → SQLite (pipeline/state.db)            │
└────────────────────────────┬────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│  2. ОРКЕСТРАТОР (возобновляемый)                                    │
│     fetch SRPM → распаковка → автоправки → mock → RPM               │
└────────────────────────────┬────────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────────┐
│  3. ПУБЛИКАЦИЯ                                                      │
│     подпись GPG → repodata → манифест                               │
└────────────────────────────┬────────────────────────────────────────┘
                             ▼
        repos/rpm/x86_64/           repos/srpm/
        (бинарный репозиторий)      (репозиторий исходников)
